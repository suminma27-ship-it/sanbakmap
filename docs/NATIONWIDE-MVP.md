# 산박지도 — 전국 공통 제품 기준 (MVP v1)

2026-11-08 · 개발 방향 확정 · 현재 화면 기능은 별도 변경하지 않음.

## 무엇을 완성으로 볼까?

**'설악산의 모든 선형을 공식 인증한 상태'가 아니라 '동일한 기능·검증 규칙으로 전국 산의 계획을 만들 수 있는 상태'**를 완성의 기준으로 한다.
앱 기능의 완성과 데이터의 현장 검증 완료는 서로 다른 작업이다. 최신 통제 정보는 별도 출처와 확인 시점을 요구한다.

### 단계별 출시 정의

| 단계 | 출하 기준 | 데이터 한계 공개 |
| --- | --- | --- |
| 전국 지도 베타 | 2,932개 산코드 검색, 전체 산 기본 선형 온라인 열람, 유형·출처 표시 | 모든 선형이 현행 허가 탐방로는 아님 |
| 코스 계획 베타 | 지원 산의 검증된 연결망에서 2개 이상 경유지 선택, 순서 변경, 실제 연결 구간의 거리·고도 표시, 저장/불러오기·내보내기 | 검증되지 않은 연결은 계산하지 않음 |
| 1.0 사용 가능 | 대표 산 20곳의 최소 60개 시나리오 회귀 확인, 모바일/PC 핵심 조작·배포 자동 검사 통과, 지원 범위 표시 | 전국 2,932개 산의 모든 구간을 동일 수준으로 검증한 것은 아님 |

대표 산 20곳과 60개 시나리오는 **앞으로 달성해야 할 합격 목표**이지 현재 검증 완료 수치가 아니다. 거리 오차 허용 기준은 동등한 원본 GPX·DEM 자료를 선정한 뒤 테스트 명세에 별도 고정한다.

## 완료 판정

이 아래 **모든 항목**이 충족되면 전국 코스 계획 **베타 완성**으로 판단한다.

- [ ] 전국 산코드 2,932개를 검색하고, 각 산의 기본 등산로를 **사용자가 ZIP 파일 없이** 열 수 있다. 원본 용량은 산별 분할/압축·지연 로딩한다.
- [ ] 한 화면에서 정상적인 등산로와 **산악 임도**를 구분한다. 인도·건물 산책로는 일반 산악 경로로 자동 승격하지 않는다.
- [ ] 들머리/갈림길/정상/대피소 등 검증된 지점을 선택해 방문 순서를 바꾸고 삭제·되돌리기 할 수 있다. 적어도 **2개 이상 경유지** 지원.
- [ ] 실제로 연결된 소스 노드만 코스를 구성한다. **검증되지 않은 구간**에서는 직선 스냅·가상 도로 생성·자동 길찾기를 하지 않고, 왜 계산되지 않는지 보여 준다.
- [ ] 경로가 유효한 경우에만 누적 거리, 총 상승·하강고도, 고도그래프를 일관된 기준으로 표시한다. 고도 자료 부재·불확실성은 숨기지 않는다.
- [ ] 코스 저장·불러오기·GeoJSON/GPX 내보내기로 다시 사용할 수 있다. 이동 중 웹/모바일 환경에서 데이터 불러오기와 패널 접기/펼치기가 작동한다.
- [ ] 소스 기관·기준일·경로 연결 증거·현행 통행 허용 검증 여부를 별도 필드로 관리한다. **OSM/GPS 좌표 일치 ≠ 현행 공식 탐방 허가**.
- [ ] 사용자가 자주 찾는 대표 산 20곳에서 최소 60개 정상·불연결·경계·순서 변경 시나리오를 테스트하고 **잘못 만들어진 연결 0건**을 확인한다.
- [ ] 모든 자동 테스트 및 GitHub Pages 배포 성공 여부를 확인하고, 모바일 실기기·데스크톱에서 동일한 핵심 흐름을 점검한다.

조건을 못 채운 산은 **'표시는 가능 / 계획은 일부 지원 / 경로 검증 미완료'** 등으로 범위를 공개한다. 일부 산의 산행 계획 미지원은 전국 지도 자체를 숨길 이유가 아니다.

## 공통 엔진 구조

```text
자료 수집 (기존 전국 산코드 2,932개 + OSM + 공식 자료)
    ↓
공통 형식 변환 (산코드, 선형, 출처, 유형, 검증 등급)
    ↓
동일 규칙으로 데이터 품질·원본 노드·출입규정 검증
    ↓
  지도 표시 / 경로 계획 연결망 / POI / 고도 / 저장
    ↓
       전국 검색 UI + 모바일 앱 UI
```

기존 `national.html`은 전국 검색·단순화 미리보기까지 있지만, **상세 GeoJSON은 사용자 ZIP 파일 선택에 의존**한다. `national-parks-trails.html`은 별도 설악산·지리산·북한산 표시 UI이고 `seorak-v96-plan.js`는 설악산 4개 POI 방문 **순서만** 저장한다. 이 둘은 현재 동일한 전국 경로 엔진으로 통합되지 않았다. 이 격차 해소가 최우선이다.

첫 코드 진입점: `core/nationwide-data-contract.js`. 신규 선형을 지도에 넣기 전 **공통 선형 분류/원본 좌표 보존/출처/비라우팅 기본값**을 정한다. 기존 산별 코드에 강제로 연결하지 않고 어댑터와 테스트가 갖춰질 때 점진적으로 연결한다.

## 일정 대신 통과 조건으로 나누는 작업

1. **공통 인터페이스:** 전국 색인·GeoJSON·OSM을 공통 선형/지점 구조에 맞추기. 산 이름이나 버전 번호를 하드코딩하지 않는다.
2. **산별 파일 배포:** ZIP 수동 첨부를 없애고 산별 압축 원본을 웹에서 불러오기. 2,932개가 모두 동일 엔드포인트 구조를 따르게 한다.
3. **공통 경로 엔진:** 원본 공유 노드 기반 연결 검증, 경유지 순서, 거리/고도 계산, 연결 불가 판정. 기존 미검증 연결 허용 옵션은 개발 진단용으로 격리한다.
4. **POI·기능 완성:** 정상·갈림길·대피소 데이터 출처 표시, 코스 저장·내보내기, 모바일 조작과 로딩 최적화.
5. **품질 게이트:** 설악산·지리산·북한산을 포함한 서로 다른 특성의 20개 대표 산에서 테스트 후 같은 규칙으로 전국 확대.

## 하지 않을 일 (MVP 바깥)

- 2,932개 산의 모든 선형을 수작업으로 하나씩 검증한 후에만 베타 공개하기
- GPX 근접도만으로 통행 가능한 길로 표시하기
- 모든 작은 건물/도시공원 산책로와 무관한 시설 POI 붙이기
- 실시간 날씨, 예약, 캠핑장 마켓, 커뮤니티, 낚시/클라이밍까지 첫 버전에 묶기
- 특정 산 접점 1건을 확인할 때마다 별도 UI 버전을 내기

## 운영 규칙 / 중단 규칙

- 신규 기능은 **전국 공통 컴포넌트 + 자동 회귀 테스트**를 먼저 만들고 대표 산에 적용한다.
- 검증 보류 건은 별도 백로그에 기록하고, 한 건 때문에 전체 개발을 멈추지 않는다.
- 출시 성공을 말하기 전 GitHub Actions 전체 테스트·Pages 업로드·배포가 통과했는지 확인한다.
- 이후 설악산 특정 접점 검증은 **공통 시스템의 데이터 갱신 작업**으로 취급한다. 전국 기능의 완료 기준 자체를 무한정 늘리지 않는다.
