## 대응 검증 조건

1. **원본 선형만 채택**: 산코드, EPSG:5179의 원본 정점 순서, 동일 구간의 정점 인덱스·양끝 좌표(≤0.22m), 누적 구간 길이(≤max(1.5m, 0.8%))를 대조.
2. **고도 누락은 중단**: 표본이 빠진 간선은 고도정보가 있는 다른 간선을 직선으로 이어 붙이지 않는다. 경로 중 하나라도 빠지면 그래프를 표시하지 않는다.
3. **출처·해상도 구별**: 90m는 길 위 재표본 간격. `output_elevation.zip`의 원본 DEM 래스터 해상도와 수직기준, 원본 래스터 SHA는 확정할 수 없어 **미확인** 상태로 표시한다. ZIP SHA는 DEM 래스터 SHA가 아니라 고도 포함 GeoJSON 산출물 ZIP의 SHA다.
4. **법적 통행 미확인**: 원본 GIS 간선 정점의 일치는 도로·탐방로의 현재 허가·개방·접점 승인을 뜻하지 않는다. 산행용 길찾기에는 사용하지 않는다.

## 전국 확장 방식

로컬 변환 결과는 산코드가 기존 `data/nationwide-topology/index.json`에서 가리키는 버킷과 같은 32개 버킷으로 분할한다. 각 산의 간선별 고도는 90m 재표본과 0.1m 양자화 후 ZigZag/varint 인코딩한다. 클라이언트 `core/nationwide-elevation-pack-v108.js`는 간선 식별자·노드 수·구간 길이·원본 SHA가 맞을 때만 복원한다.

ZIP 산출물 안에는 32개 버킷과 산별 대응 성과를 기록한 `coverage-v109.json`, 재현 가능한 `build_v109.py`를 포함한다. 추후 버킷을 GitHub Pages 정적 파일로 추가하고 색인만 갱신하면 **같은 페이지·같은 고도엔진으로** 확대된다.

이 작업은 고도 데이터 출처 일치 검증이며 최신 국립공원 탐방정보 검증과는 별도다.
